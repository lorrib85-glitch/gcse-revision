# Phase 4 — Component Lab design

Turn the Component Review Lab into an **owner-facing projection of the canonical
component catalogue**, without turning the catalogue into a UI toolkit.

Read `CENSUS.md` first — every claim below rests on a measured number there.

---

## 1. The three layers

### Layer 1 — catalogue-generated Lab facts

A new generated projection, `src/data/generated/componentLabRegistry.js`,
produced by `scripts/generate-lab-registry.mjs` from the canonical catalogue,
following the exact pattern already proven twice (`componentAuthoringRegistry.js`,
`componentPedagogyRegistry.js`): `pnpm lab:generate` writes it,
`pnpm lab:check` fails on drift.

**One entry per catalogue record**, keyed by record id. Fields, all lifted
directly from the record or from a deterministic scan:

| Field | Source |
|---|---|
| `id`, `name` | record |
| `source`, `exportName` | record |
| `section`, `kind` | record |
| `lifecycle`, `lifecycleReason` | record |
| `criticality`, `hasExclusivity` | `record.contract` |
| `decisionStatus` | `record.decision.status` |
| `bestUsedFor` | `record.documentation.bestUsedFor` |
| `useWhen`, `doNotUseWhen`, `chooseInstead`, `contentShape` | `record.decision` |
| `rhythmRole` | `record.decision.rhythmRole` |
| `authoring` | `[{ level, type, authoringName, status, layout }]` — **level-aware** |
| `pedagogy` | per authoring entry: `{ functions, interaction }` |
| `contentUsage` | `{ occurrences, files }` per authoring type — generated by scanning `src/content/**` |

**This file is production-safe and contains no JSX, no functions and no React.**
It is exactly the kind of lean generated source the settled boundaries permit the
Lab to consume.

`contentUsage` is generated by the same scan that produced
`baselines/current-content-type-usage.json`. **It must match both authoring
styles** (`type: 'x'` and `"type": "x"`) — the census showed that matching only
the first reports `spotTheError`, `builder` and `acronymMemorise` as unused when
they are not. That is the exact bug that made the current Lab prose wrong.

### Layer 2 — handwritten preview adapters

Stays handwritten, stays in `src/dev/componentReview/`. An adapter is keyed by
**catalogue record id** and carries only what cannot be a serialisable fact:

```
{
  recordId: 'timeline-chain',        // the join key — not a second identity
  presentation: 'preview',           // 'preview' | 'reference'
  renderMode: 'fullbleed',           // Lab framing, not authoring layout
  subject: 'History',                // which palette the *example* uses
  fixture: FIX.timelineChain,
  render: (fx, { onDone }) => <TimelineChain … />,
  variants: [ { id, label, description, fixture?, renderMode?, render } ],
  reviewNote: '…',                   // optional, Lab-only
}
```

Everything the census classified as **D — preview adapter fact** lives here and
nowhere else: React imports, JSX, fixtures, GCSE examples, subject/accent choice,
inline vs full-bleed, callbacks, interaction setup, controlled state,
variant props, reset/replay, and sanctioned layout overrides such as the in-flow
`CinematicContinueCTA` and the 320px `mobile-width` variant.

**Nothing from this layer is ever promoted into a catalogue record.**

### Layer 3 — Lab shell

`ComponentReviewLab.jsx` composes the index from Layer 1 joined to Layer 2 by
`recordId`. It renders generated facts and mounts handwritten adapters. It
authors no facts of its own.

The join is the governance point: **a Lab entry with no `recordId` is a build
error**, except for the one sanctioned Lab-local page (`buttons-and-progress`,
which is a reference page, not a component).

## 3. The index and filter model

`status` is deleted. It fused five unrelated ideas, went stale twice, and 33 of
49 entries carried the same meaningless value (`comparison`).

The index filters on four **generated** facts plus one adapter fact:

1. **Lifecycle** — `active` / `reviewing` / `parked` / `internal`
2. **Authorability** — none / screen / block / both
3. **Content usage** — occurrence and file counts
4. **Decision readiness** — `complete` / `pending` / `not-applicable` / none
5. **Presentation kind** (adapter) — `preview` / `reference`

The old labels become *derived filters over facts*, so they cannot go stale:

| Old status | Derived predicate |
|---|---|
| `unused` | `authoring.length === 0` |
| `routed-unused` | `authoring.length > 0 && contentUsage.occurrences === 0` |
| `one-off` | `contentUsage.occurrences === 1` |
| `comparison` | *(dropped — carries no information)* |
| `reference` | `presentation === 'reference'` |

Under this model the two census errors are structurally impossible:
`spot-the-error` (1 use) stops claiming to be unused, and `timeline-chain`
(8 uses) stops claiming to be a one-off.

Grouping stays by pedagogical interaction class, now read from the generated
projection rather than `getTypeInfo()`. The dead `uncategorised` label — which
the census proved never fires — is dropped.

## 4. Coverage target

The Lab currently represents 56 of 84 records. The target is that **every record
is accounted for in the index**, with the index distinguishing three states the
current Lab conflates:

| State | Count | Behaviour |
|---|---|---|
| Mountable preview | 72 | Listed and openable |
| Listed, not mountable | 9 | Listed with its facts and a stated reason; no preview frame |
| Deliberately absent | 3 | `InlineNavigationContext`, `HomeAtmosphere`, `ExaminerExplainsScreen` |

New adapters needed, in priority order (census evidence in brackets):

1. `ExamQuestionFrame` — [61 content uses, most-used authorable type with no preview]
2. `PriorKnowledgeRecall` — [6 uses, active reusable]
3. `RecoveryQuizPlayer` — [active reusable, decision complete]
4. `FractionRatioExplore` — [its four Explore siblings are all previewed]
5. `TimelineChainBlock` — [as a level variant of `TimelineChain`, not a new identity]
6. The ten support primitives missing from the reference page, including the two
   authorable blocks `MediaPlaceholder` and `AnswerInteraction`
7. The seven visual runtime/layout components (`InteractionShell`,
   `CinematicShell`, `ProgressRecoveryCard`, `ExamRoundDebrief`, `RetrievalFrame`,
   `UnifiedQuestionScreen`)

### Identity corrections

- **`face-the-examiner` must mount the public export.** The Lab currently imports
  `faceTheExaminer/FaceTheExaminerContainer.jsx` — a directory the record claims
  as an internal. Switch the import to `FaceTheExaminer.jsx` and display the
  catalogue name. Behaviour is identical (the public file is a bare re-export).
- **Duplicate entries collapse into variants.** `GraphView` ×2,
  `InteractiveHotspotImage` ×2 and `BuilderBlock` ×3 become three entries with
  variants — six entries becoming three, with no preview lost.
- **The "internal child" comment at `reviewManifestCore.jsx:64-68` is deleted.**
  It contradicts the catalogue for `UnifiedQuestionScreen` and
  `RecoveryQuizPlayer`, both of which hold their own active records.

## 5. Removing the Phase 3 temporary pedagogy entry

`src/component-catalogue/migrations/nonAuthoringPedagogy.js` carries one entry,
`calculationBreakdown`, whose stated removal condition is:

> Delete this entry when Phase 4 replaces the Lab manifest's getTypeInfo
> dependency, or when CalculationBreakdown receives a genuine authoring entry —
> whichever happens first.

**Exactly when and how it is removed.**

*When.* The moment `reviewManifestCore.jsx:949` — the sole
`getTypeInfo(entry.contentType)` call in the Lab — is deleted, and the Lab's
interaction badge is read from `componentLabRegistry.js` instead. The census
confirmed the Lab is the only consumer of this classification: the one other
`getTypeInfo` caller, `src/data/contentQualityChecks.js`, resolves types found in
authored content, and `calculationBreakdown` has **zero content uses**, so it
never asks for it.

*How.* In the same commit that removes the Lab's `getTypeInfo` import:

1. Delete the `calculationBreakdown` entry from `NON_AUTHORING_PEDAGOGY`,
   leaving the array empty.
2. Run `pnpm pedagogy:generate` and commit the regenerated
   `componentPedagogyRegistry.js`, which drops the now-unreferenced classification.
3. Verify `pnpm pedagogy:check` passes.

**`CalculationBreakdown` must not be given a fake authoring entry.** It has no
authorable screen or block type, and inventing one to tidy the registry would put
an unauthorable type in front of authors. The Lab shows it because it is a
catalogued component under review — which the generated Lab projection expresses
directly, without any pedagogy classification being required.

Once the array is empty, the file itself stays (with its governing comment) so a
future addition still goes through the same explicit decision.

## 6. Source-comment corrections

The implementation may correct the false production-boundary claims catalogued in
Census 1 — `ComponentReviewLab.jsx:3-5`, `reviewManifestCore.jsx:3` and `:9`,
`ButtonsAndProgressPage.jsx:3`. Replacement wording should match the already
accurate `src/App.jsx:5-11`: a production-bundled, lazily loaded owner tool that
learners never navigate to.

**This changes comments only.** Access model, query flag, entry card, auth bypass,
app-replacement behaviour, exit behaviour, URL structure and learner reachability
are all parked by the settled boundaries and must not move.

## 7. Bundle position

The Lab's own chunk is 356.16 kB raw / 105.76 kB gzip, downloaded only when the
owner sets the flag, with no leakage into the learner entry (measured).

**No code-splitting change is in scope for Phase 4.** The census recorded three
options in `baselines/current-bundle-baseline.md`; none is adopted here. Phase 4
adds adapters, which will grow the chunk — the implementation plan requires the
chunk to be re-measured and the delta reported, not held to a budget.

---

## 8. What this design refuses to do

- Put JSX, render functions, fixtures or React imports into catalogue records or
  generated data.
- Let the Lab restate any fact the catalogue owns — name, purpose, alternatives,
  lifecycle, authorability, pedagogy.
- Promote `status`, `subject`, `renderMode` or variant prose into the catalogue
  because the Lab happens to display them.
- Give `CalculationBreakdown` an authoring entry it has not earned.
- Create standalone identities for private family internals.
- Touch the access model, Storybook, or `src/component-catalogue/**` imports from
  the runtime.
